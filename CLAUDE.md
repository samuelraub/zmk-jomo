# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ZMK user config for the **Jomo**, a 36-key split keyboard (2 × nice!nano v2,
3×5 + 3 thumbs per half). There is no local toolchain: firmware is built only
by GitHub Actions.

## Build

- Push (or open a PR / `workflow_dispatch`) and `.github/workflows/build.yml`
  runs ZMK's reusable `build-user-config.yml@v0.3`. The firmware `.uf2` files
  are the run's artifacts. `gh run list` / `gh run watch` / `gh run download`
  to follow and fetch them.
- `build.yaml` is the build matrix: `jomo_left`, `jomo_right` and
  `settings_reset`, built without ZMK Studio (artifacts use ZMK's default
  names, e.g. `jomo_left-nice_nano_v2-zmk.uf2`).
- ZMK is pinned to `v0.3` in both `config/west.yml` and the workflow; bump them
  together.

## Keymap diagram

`jomo_keymap.yaml` and `jomo_keymap.svg` (shown in the README) are generated by
keymap-drawer (`keymap`, installed via pipx). Regenerate both after any keymap
change:

```sh
keymap parse -c 10 -z boards/shields/jomo/jomo.keymap > jomo_keymap.yaml
keymap draw -d boards/shields/jomo/jomo-layouts.dtsi jomo_keymap.yaml > jomo_keymap.svg
```

`-d` is required: keymap-drawer has no built-in layout for `jomo`.

## Layout of the config

The repo is both the ZMK config (`config/`) and a Zephyr module
(`zephyr/module.yml`, `board_root: .`) that supplies the shield in
`boards/shields/jomo/`. The keymap lives in the shield directory, not in
`config/`.

- `jomo.dtsi` — shared kscan (col2row matrix) and the 10×4 matrix transform;
  `jomo-layouts.dtsi` — physical layout (required by ZMK, used by keymap-drawer).
- `jomo_left.overlay` / `jomo_right.overlay` — per-half GPIO pins. The right
  half sets `col-offset = <5>`. Each half wires one row + one column as a
  soft-off wakeup source; those pins must stay in sync with the kscan pins.
- `Kconfig.defconfig` — the left half is the split central; keyboard name must
  be < 16 chars.
- `config/jomo.conf` — Kconfig for both halves (sleep, soft off, pointing, BLE
  tweaks).

## Keymap conventions (`jomo.keymap`)

- Key positions 0–29 are the 3×10 alpha block, 30–32 left thumbs, 33–35 right
  thumbs; `KEYS_L`/`KEYS_R`/`THUMBS_L`/`THUMBS_R` name these sets.
- Colemak-DH base with home-row mods (`hml`/`hmr`) and thumb layer-taps
  (`ltl`/`ltr`). All four are custom hold-taps using positional
  `hold-trigger-key-positions` (opposite hand + thumbs) with
  `hold-trigger-on-release`; `QUICK_TAP_MS` is shared.
- Layers are indexed by position (`// Layer N` comments); each thumb key holds
  the layer with the same index (1 tmux … 6 media). Reordering layers means
  updating the `&ltl`/`&ltr` arguments.
- The layer-tap's own thumb on each layer is left as `&none` (shown as "held"
  in the diagram).
- The `tmux` macros send `RA(T)` first, then the `C-a` prefix. ⌥T is an Alfred
  hotkey (AppSwitcher workflow) that focuses kitty, so they work from any app;
  `&tmux_copy` skips it and needs kitty focused already.

## Host-side setup (macOS)

Alfred's AppSwitcher workflow binds ⌥+key to launch/focus an app: ⌥T kitty,
⌥G Chrome, ⌥B Firefox, ⌥F Finder, ⌥C Calendar, ⌥M Thunderbird, ⌥L Signal,
⌥1 1Password. Keymap bindings that switch apps should send these (`RA(<key>)`)
rather than define new hotkeys. With the opposite-hand home-row mods, ⌥ for a
left-hand letter comes from the right hand (hold E) and vice versa (hold S).
